# Chapter 3: filler-augmented training

*One training-time trick that gets the mixer through the depth wall.*

This is the chapter write-up. For the big picture and how it connects to chapters
1 (FENRIR) and 2 (FREKI), see the [top-level README](../README.md). The full
write-up is in [`paper/`](paper/).

FILLER is not an acronym; it is literally what the trick inserts. It stands as the
third step in the line: FENRIR showed the mixer *can* chain a couple of hops,
FREKI made chaining reliable inside a layer, and this chapter is about what breaks
when you push the same mixer *deeper*, and the one change that fixes it.

## The problem: three ways depth breaks

Take the eager-closure fast-weight mixer from chapter 1 and train it on longer
chains (5 or 6 hops). Instead of one clean failure, you get three tangled ones:

1. **Query-conditioned formation.** A seed looks like it solved the task, but its
   answer actually leans on the tokens sitting right next to the question, not on
   the memory it built up. Slip even a few filler tokens between the last fact and
   the question and the answer falls apart.
2. **State divergence.** Past a certain sequence length the model's internal
   activations grow without bound, and the readout latches onto whatever direction
   the blow-up happens to point in.
3. **The depth wall.** Beyond a certain number of hops, no healthy seed forms at
   all. The baseline recipe just cannot get there.

## The trick

One change to *training*, nothing to the model: between the last fact and the
question, insert a **random number of filler tokens** (a warm-up with no filler
for the first 2,000 steps, then a ramp from 0 up to 200 over the next 2,000),
alongside the existing two-part loss (a one-hop probe next to the full K-hop
target). That is the whole intervention. The idea is that if the model is forced
to answer with a varying gap between the facts and the question, it cannot lean on
what sits next to the question, so it has to use the memory instead, which
happens to fix all three failures at once.

## What happened

The headline is the 6-hop cell, where the plain recipe hits the wall and the
filler recipe gets through. Passing means all three checks at once: it solves the
chain even with filler in the way (target accuracy at 200 fillers ≥ 0.80), it does
not lean on the question (QTOK-flip ≤ 0.15), and it does not blow up (div_norm
under 1,000).

| recipe | seeds | pass rate | target @200 filler | QTOK-flip | state norm @2000 filler |
|---|---|---|---|---|---|
| baseline | 3 | **0/5 healthy** | 0.45 (one seed near chance, one query-adjacent, one diverged) | 0.32 | one seed at 1.2×10⁹ |
| **filler** | 5 | **4/5 pass** | 0.87 (passers) | ≤ 0.02 | ≤ 78 |

The recipe holds across 3, 4, 5, and 6 hops, and a separate two-layer version of
the same architecture solves the 3-hop task at 0.992 accuracy across three seeds.

**The honest caveat, which is in the paper too:** at depth the recipe biases the
model toward expecting filler, so passing seeds increasingly need *some* filler
present at evaluation to reach their best accuracy. The trick buys robustness to
separation; it does not come entirely free.

## The metrics

- **target accuracy** at 0 and 200 fillers: does it solve the chain, and does it
  survive facts and question being pulled apart.
- **QTOK-flip**: the fraction of predictions that change when the question token is
  half-occluded, measured with 200 fillers present. Above 0.15 means the model is
  leaning on the question rather than on its memory (see `probe.py`).
- **div_norm at 2000 fillers**: the largest internal activation norm at the end of
  a very long sequence. Above 1,000 means it is diverging.

## How to run it

Plain PyTorch. The eager-closure mixer is torch-only, so the pipeline (and a CPU
smoke test) runs without a GPU; reproducing the real numbers needs one.

```bash
pip install -r ../requirements.txt

python filler/experiments/01_depth_wall_hops6.py --smoke   # tiny CPU check
python filler/experiments/01_depth_wall_hops6.py --full    # baseline n=3 + filler n=5 (GPU)
python filler/experiments/02_depth_sweep.py --full         # filler across 3..6 hops (GPU)
```

## Layout

```
model.py         the eager-closure fast-weight mixer (sequential + chunk-parallel) + stack
chunked_core.py  the chunk-parallel kernel (self-tests to 1e-15)
nhop_task.py     the N-hop chain task sampler + insert_filler
tasks.py         control tokens, task config, pair sampler
probe.py         div_norm and the occlusion probe (QTOK-flip)
sweep.py         one training run (baseline or filler recipe)
util.py          seeding, timing, result writing, LR schedule
experiments/     01 the 6-hop depth wall, 02 the 3-to-6-hop sweep
paper/           the compiled paper (PDF + LaTeX source)
results/         per-run JSON (git-ignored; regenerated by the sweeps)
```

The model here is chapter 1's eager-closure mixer, unchanged; this chapter is
only about what happens when you push it deeper and train it with filler. The
compiled paper is in `paper/`.
